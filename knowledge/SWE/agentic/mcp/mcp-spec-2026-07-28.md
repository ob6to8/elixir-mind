# The MCP 2026-07-28 specification

Superseding revision **2025-11-25** (per the [MCP architecture](/knowledge/SWE/agentic/mcp/mcp-architecture.md)
capture's note), 2026-07-28 replaces the [stateful client-host-server session](/knowledge/SWE/agentic/mcp/mcp-architecture.md)
model with a stateless request/response core — David Soria Parra calls it "MCP's
most important [revision] since remote MCP first launched", and the community
chose breaking changes over deferring the architectural problem after eighteen
months of production feedback.

## The stateless core

Previously, `initialize`/`initialized` plus an `Mcp-Session-Id` header
maintained a persistent, stateful session per the
[architecture note's](/knowledge/SWE/agentic/mcp/mcp-architecture.md) model. Under
2026-07-28, every request is self-contained — protocol version, client
identity, and capabilities travel in `_meta` on each call — so no handshake is
required and **any request can land on any server instance** behind a plain
load balancer with no shared session store. An optional `server/discover` RPC
lets a client learn capabilities upfront, but it is no longer mandatory.
Protocol-level statelessness doesn't force application statelessness: a server
that needs to carry state across calls mints an explicit handle (e.g. a
`basket_id`) from a tool, and the model threads it back as an ordinary argument
on later calls.

## Multi Round-Trip Requests (MRTR)

Server-initiated mid-call patterns — `elicitation/create`,
`sampling/createMessage`, `roots/list` — required a held-open stream, which is
awkward for a stateless core. MRTR replaces them: a tool call that needs
confirmation or a missing parameter returns `resultType: "input_required"`, and
the client retries the original call with answers attached in
`inputResponses`. The interaction becomes poll-based rather than
stream-based.

## Header-based routing and cacheable lists

Streamable HTTP requests now carry mandatory `Mcp-Method` and `Mcp-Name`
headers, so gateways, rate limiters, and WAFs can route and meter traffic
without parsing JSON bodies. Responses from `tools/list`, `prompts/list`,
`resources/list`, and `resources/read` carry `ttlMs` and `cacheScope`, letting
clients cache results for as long as the server permits instead of re-fetching
every session.

## Authorization hardening

Several changes close gaps found in production OAuth deployments — the
[MCP tools primitive](/knowledge/SWE/agentic/mcp/mcp-tools-primitive.md) capture's
trust rules now sit on a formally OAuth 2.1/OIDC-aligned base:

- **RFC 9207 issuer validation** — authorization servers return the `iss`
  parameter, and clients must validate it before redeeming a code, closing
  authorization-server mix-up attacks.
- **Client ID Metadata Documents (CIMD)** become the standard client-identity
  mechanism; Dynamic Client Registration (DCR) is formally deprecated but stays
  functional through a twelve-month minimum deprecation window. DCR also gained
  an `application_type` field in the interim, stopping authorization servers
  from rejecting `localhost` redirects for desktop/CLI clients.
- **Credential binding** — client credentials bind to the specific
  authorization server that issued them, preventing reuse across providers.

This is what lets MCP servers connect to enterprise identity systems (Entra,
Okta) without workarounds, and formally makes an MCP server an OAuth 2.1
resource server.

## Tasks becomes a formal extension

Tasks graduates from experimental core to the `io.modelcontextprotocol/tasks`
extension, joining MCP Apps and Enterprise Managed Authorization (EMA) in a
now-locked-in extensions framework. Streaming task updates are replaced by
poll-based `tasks/get`, a new `tasks/update` for status changes, and change
notifications consolidate onto one `subscriptions/listen` stream with
per-notification-type opt-in.

## Deprecations and rollout

Roots, Sampling, and Logging — all part of the older stateful/streaming
model — move to deprecated status, alongside the legacy HTTP+SSE transport,
each with a minimum twelve-month support window. All four Tier-1 SDKs
(TypeScript, Python, Go, C#) shipped support for `2026-07-28` simultaneously;
Rust is in beta. One reported side effect: SDK v2's client-server split cut
package size 83% and raised throughput 25%. The ecosystem is near half a
billion Tier-1 SDK downloads a month, which is the scale the stateless
rewrite is sized for.
