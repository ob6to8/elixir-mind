# Decide whether the Workflow fan-out convention graduates

[Executing ratified plans via Workflow fan-out](/meta/analysis/executing-ratified-plans-via-workflow-fan-out.md)
proposes a convention for running a ratified plan through fresh-context agents:
an execution spec, a readiness gate, a fold-back triangle, and a write-partition.
It closes with four open questions and asks whether it should graduate.

**Why it needs deciding now rather than later.** Per
[governance-artifact-routing](/meta/policy/governance-artifact-routing.md), an
analysis concludes with a *judgment*; a plan commits to *work*. An analysis whose
residue is action is meant to be retyped as a plan, not left as an analysis
indefinitely — and an analysis is invisible to `/priorities`, so leaving it here
means it is never picked up.

**The four open questions** (in the analysis, § 6): pilot choice,
execution-record home, mandate vs. recommend, and whether worktree isolation is
the default.

**A natural pilot exists.** The
[strand reconciliation plan](/meta/plans/reconcile-dangling-ledger-strands.md)
has steps 2–5 that are mechanical, well-specified, and explicitly intended for
fresh-session execution — close to the shape this convention describes.

**Done when.** The convention is graduated into a `type: plan` with the four
questions answered, or declined with the reason recorded so the analysis stops
reading as pending work.
